# Issue #2 — local transfer and Mac remote

Status: frozen on 2026-08-25.

## Goal

Close the remaining shared-workflow gap in `kiku-jw/kyuva#2` without adding an
account, cloud service, dependency, or automatic synchronization: move one
plain-text script between Mac and iPhone through Apple's standard share/file
surfaces, and let an explicitly paired iPhone control the active Mac prompt
over an encrypted local session.

This is a new slice after the accepted `issue-2-apple-suite` task. It does not
rewrite that frozen historical acceptance packet or change the already uploaded
macOS `1.0 (1)` binary.

## Scope

- Add iPhone plain-text import and share/export; reuse the Mac's existing
  plain-text import/export for deliberate AirDrop/Files transfer.
- Add a Mac-only Bonjour listener and iPhone-only Bonjour browser with
  `Network.framework` on the existing macOS 13 / iOS 17 minimums.
- Authenticate and encrypt each local session with TLS-PSK derived from a new
  random 16-character, 80-bit pairing code shown only in the Mac UI and entered
  explicitly on iPhone.
- Keep pairing ephemeral: starting the Mac remote creates a code; stopping,
  disconnecting, or quitting rotates it and removes the session.
- Carry only versioned, bounded remote commands and playback snapshots over the
  custom channel. Script content never uses the custom channel.
- Preserve the existing iPhone-to-Watch `WatchConnectivity` remote.

## Acceptance criteria

- **AC1 — standard local transfer:** iPhone imports a user-selected UTF-8 plain
  text file as a new local script and shares the selected script as a `.txt`
  file. A fresh physical-device pass proves Mac-to-iPhone and iPhone-to-Mac
  transfer through system AirDrop/Files surfaces without a Kyuva server.
- **AC2 — explicit encrypted pairing:** the Mac advertises only after the user
  starts a remote session; iPhone browses only while its Mac Remote surface is
  open. A correct 80-bit code establishes TLS-PSK, a wrong code fails visibly,
  and there is no plaintext fallback, persisted token, account, or internet
  relay.
- **AC3 — bounded remote protocol:** only request snapshot, play/pause, reset,
  faster, and slower are accepted. Requests contain protocol version and a
  strictly increasing sequence; malformed, oversized, unknown, wrong-version,
  duplicate, or replayed messages are rejected. One message is at most 4 KiB
  and one Mac session accepts at most one iPhone.
- **AC4 — usable Mac remote:** a connected physical iPhone shows prompt title,
  play/pause state, pace, progress, and a visible error when the Mac prompt is
  hidden or unreachable. Its five controls change the active Mac prompt and
  receive an acknowledged snapshot.
- **AC5 — configuration and privacy truth:** the Mac sandbox has only the
  network-server and network-client capabilities needed for incoming TCP and
  Bonjour's outbound mDNS advertisement; Mac and iPhone declare the exact
  Bonjour service and local-network explanation. No multicast entitlement,
  camera, microphone,
  Speech, analytics, advertising, StoreKit, backend, or third-party package is
  added. `PRIVACY.md` truthfully distinguishes user-initiated encrypted local
  communication from developer data collection.
- **AC6 — release identity:** source advances to version `1.0` build `2` for
  changed Mac/iPhone/Watch products. App Store Connect remains on the already
  uploaded macOS `1.0 (1)` draft until a separately approved upload; no current
  Store state is inferred from source.
- **AC7 — deterministic proof:** all Swift package tests pass; unsigned macOS
  universal Release, iOS Release, and watchOS Release builds pass from disposable
  directories; product inspection confirms identifiers, embedded Watch app,
  privacy manifests, Bonjour keys, and entitlements. A fresh read-only verifier
  records PASS/FAIL/UNKNOWN for every criterion.
- **AC8 — physical regression proof:** the current build installs on Nick's
  connected iPhone 15 Pro and paired Apple Watch Series 10; physical
  iPhone-to-Mac remote commands work; iPhone-to-Watch controls still work; real
  iPhone prompt viewport and idle-sleep behavior are checked. Device facts not
  directly observed remain `UNKNOWN`.
- **AC9 — owner gates:** no build upload, accessibility-card publication, Add
  for Review, submission, release, agreement, credential, OTP, 2FA, keychain
  password, or irreversible provider action occurs in this slice.

## Constraints

- Native SwiftUI, Foundation, CoreTransferable, CryptoKit, Security,
  Network.framework, and existing WatchConnectivity only.
- The pairing code alphabet excludes ambiguous characters and is generated by
  `SecRandomCopyBytes`; normalization accepts spaces and hyphens only.
- Bonjour metadata contains no personal device name, script title/content,
  contact information, or stable identifier.
- Never log a pairing code, derived PSK, script content, or private device data.
- Preserve unrelated work and the accepted historical evidence bundle.

## Non-goals

- Cloud sync, accounts, automatic merging, background sync, live script edits,
  persistent pairing, browser/internet remote, team collaboration, or a custom
  network file-transfer protocol.
- Direct Watch-to-Mac networking; Watch remains dependent on its paired iPhone.
- Recording, camera, speech following, AI rewriting, subscriptions, or
  monetization.
- Replacing or resubmitting the uploaded macOS build `1.0 (1)` without a new
  owner instruction.

## Assumptions

- A 16-character base-32-style code supplies 80 bits of random entropy and is
  practical to enter once per deliberate local session.
- Apple system share/file UI is the simplest accessible transport for scripts;
  the custom TLS channel is justified only for immediate remote commands.
- `Data Not Collected` remains accurate because Kyuva's developer receives no
  data; the two user-owned devices communicate directly after an explicit
  action.

## Kill gates

- If TLS-PSK plus Bonjour does not build and connect on both macOS 13 and iOS 17
  APIs, do not ship plaintext TCP or deprecated MultipeerConnectivity; accept
  file transfer only and leave Mac remote `UNKNOWN`.
- If a wrong pairing code can reach command handling, if replay/oversize tests
  fail, or if private content appears in Bonjour/logs, stop the slice.
- If physical testing requires credentials, keychain passwords, 2FA, provider
  changes, or a new entitlement approval, stop before that action.

## Verification plan

3. Run fresh SwiftPM tests and macOS/iOS/watchOS Release builds in a validated

4. Install signed development builds only if existing signing works without a

5. Use the physical iPhone and paired Watch for the AC4/AC8 matrix, preserving

6. Run a fresh verifier that edits no production code, then finalize the task
